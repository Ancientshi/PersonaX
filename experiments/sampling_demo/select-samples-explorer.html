These external geometric diagnostics help interpret selection; they are not paper performance metrics. Distances use the scaled input coordinates, so their values also depend on input scale.

Reading the results

alpha controls the weights. Each step maximizes easy + diversity, where easy = w_p / (1 + distance_to_centroid). At alpha = 1, the diversity weight is zero. Increasing alpha gives the distance-based diversity term more weight, but a parameter change does not always change the selected points.

The code's diversity term differs from the usual mean pairwise distance. After adding a candidate, it sums distances over all unordered pairs, divides by the number of points, and multiplies by w_d. The diagnostic above divides by the number of pairs instead. At the first step there is only one point, so diversity is zero.

Input scale also affects the trade-off. Scaling coordinates up increases the distance sum and reduces 1 / (1 + distance_to_centroid). Selection order can therefore change even at fixed alpha. Both plots share the same scale and axes; changing input scale rescales the axis labels while keeping relative point positions the same.

Parameter limits. Use finite alpha ≥ 1 for the intended weighting. The input should be a nonempty, finite numeric array with shape (N, d); this example has N = 44, d = 2. Use an integer num_samples with 1 ≤ k ≤ N. The original function also accepts k = 0 and returns an empty selection; this page shows nonempty selections.

Determinism. The function uses no random numbers: the same input and order give the same result. Seed 42 is used only to generate the synthetic points. When candidate scores tie, the function prefers the earlier input index.
