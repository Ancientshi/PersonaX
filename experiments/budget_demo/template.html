Floor share is the remaining budget divided by the remaining cluster count, rounded down. Rows use the function's actual NumPy sort order; the output above is restored to original input order.

Reading the allocation

Approximately equal counts, not proportional shares. The function visits clusters from smallest to largest. Each receives the smaller of its size and the current floor share. Filling a small cluster leaves more budget for the remaining clusters.

Budgets below the cluster count are raised. With positive cluster sizes, the effective budget gives every cluster at least one item. All examples have 4 clusters and 32 items; requested budgets from 0 to 3 therefore become 4. The final unallocated budget is zero throughout the displayed range.

From ratio to budget. The sampling wrapper first computes ceil(total_size × ratio), then passes that budget to get_allocation. The minimum budget rule still applies.

Safe inputs for this demo. Cluster sizes are positive integers; the requested budget is an integer in 0..N, where N is their sum. The original function does not validate these limits or safely cap budgets above total capacity. NumPy's argsort is not explicitly stable for equal sizes, so no fixed tie priority is assumed.
